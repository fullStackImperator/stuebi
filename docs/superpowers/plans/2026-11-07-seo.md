# SEO Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Die neue Seite übernimmt stuebi-hamburg.de ohne Ranking-Verlust: alte Adressen leiten weiter, jede Seite hat kanonische Adresse, Vorschau und Beschreibung, Google erkennt Schule, Beiträge und Termine.

**Architecture:** Eine Domain-Konstante und ein Metadaten-Helfer (`src/lib/site.ts`, `src/lib/page-metadata.ts`) speisen Layout, Seiten, Sitemap und robots.txt. Alte Adressen löst eine reine Funktion (`src/lib/old-site-redirect.ts`) gegen eine Datenliste auf; eine Route unter `/stadtteilschule/[...path]` antwortet mit 308. Strukturierte Daten baut `src/lib/structured-data.ts`, ausgegeben über eine kleine `JsonLd`-Komponente.

**Tech Stack:** Next.js 16 (App Router, Metadata-API, `sitemap.ts`/`robots.ts`/`opengraph-image`), Payload 3 Local API, Playwright (Projekte phone und desktop; Unit-Tests als `e2e/*.unit.spec.ts`).

**Spec:** docs/superpowers/specs/2026-11-07-seo-design.md

## Global Constraints

- Live-Domain: `https://stuebi-hamburg.de` – nur als Konstante `SITE_URL` in `src/lib/site.ts`.
- Live-Erkennung: `process.env.NEXT_PUBLIC_SERVER_URL === SITE_URL`; sonst sperrt robots.txt alles.
- Alle Weiterleitungen von der alten Seite: Status **308**.
- Titel-Vorlage: `%s | Stübi Hamburg`; Startseite behält „Stübi Hamburg – Die andere Schule | Von der Vorschule bis zum Abitur“.
- Beschreibungen: höchstens **150 Zeichen**.
- Vorschaubild: **1200×630**.
- Events nur für CMS-Termine der Arten `info` und `event` (inkl. Tag der offenen Tür); nie `registration`, nie IServ.
- Vor dem Schreiben von Next-Code die passende Doku in `node_modules/next/dist/docs/01-app/03-api-reference/03-file-conventions/01-metadata/` lesen (sitemap.md, robots.md, opengraph-image.md).
- Code-Stil wie umgebend: einfache Anführungszeichen, keine Semikolons, lange Zeilen. Kein Prettier mit Standardwerten.
- `.env` zeigt auf die Live-Datenbank: nur lesen. Commits nur mit eigenen Dateien und Hunks (`git commit -- <pfade>`), Nachrichten auf Deutsch mit `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Nicht pushen.
- Nach CSS- oder Komponentenänderungen, die der Dev-Server nicht zeigt: `lsof -ti:3000 | xargs kill; pkill -f "next dev"; rm -rf .next/dev/cache/turbopack; nohup npm run dev &`.

## Review Focus

- Alte Adresse mit Query-String (`…/bob-team/?fbclid=…`) oder Fragment → wird wie ohne aufgelöst, Query fällt weg. (Test in Task 3.)
- Alte News-Adresse ohne Datum-Präfix, z. B. `/stadtteilschule/stuebi-faehrt-fahrrad/` → wenn Slug im CMS: Beitrag, sonst Startseite – nie 404. (Test in Task 3.)
- Beitrag mit Status `draft` im CMS → Weiterleitung auf `/news`, nicht auf eine 404-Beitragsseite. (Test in Task 3, Unit mit `hasNews` = false.)
- Termin mit Uhrzeit im Sommer vs. Winter → Event-`startDate` mit `+02:00` bzw. `+01:00`. (Test in Task 5.)
- Termin mit Freitext-Uhrzeit ohne Zahlen („ganztägig“) oder ohne Uhrzeit → Event nur mit Datum, kein kaputtes ISO. (Test in Task 5.)
